# CLAUDE.md

This file provides guidance to Claude Code when working with code in this repository.

CLAUDE.md and AGENTS.md carry the same text. Change both together.

`aicc-knowledge` is a single-tenant knowledge retrieval service for AICC, the AI Native Call Center. AICC calls it as an ordinary flow HTTP tool and never depends on it. Source files live in S3. PostgreSQL is the source of truth. Meilisearch is a derived index that can always be rebuilt. The license is Apache-2.0. The evidence behind the decisions below is in `docs/research/README.md`. Read caveats C1–C7 there before touching search, publish or the dev stack.

## Real data is private (read first)

This repository is **public**. Real customer documents and real caller questions are test material only.

- **No trace in git.** Do not commit them, or anything derived from them: no fixtures, file names, excerpts, questions, answers, eval CSVs, example results, or mentions in docs, commits, PRs or issues. Committed fixtures are synthetic and are generated by `internal/docx/testdata/gen` and `internal/xlsx/testdata/gen`.
- **Desensitize before ingesting.** Work on copies outside the repo; never modify the source directory.
  - Mask: person names, phone numbers, emails, physical addresses, order, ticket and serial numbers, call ids, IPs, URLs and hostnames, and document author metadata.
  - Strip embedded images. The service does not OCR them, but they can carry personal data.
  - Keep product and feature names, because they are what the FAQ is about.
  - Use consistent placeholders (`[PHONE_1]`).
  - Verify with a residual regex scan and a manual spot check.
  - Delete the original-to-placeholder mapping and any raw text extracts afterwards.
- **Local services only.** Use the compose stack and a local OpenAI-compatible LLM. Never use cloud LLM keys found in the environment.
- **Isolate every run.** Use a scratch database, its own S3 prefix and its own `KB_MEILI_INDEX_PREFIX`, and clean all three up afterwards.
- **Check before every commit or push.** Grep the staged diff for data-derived content.

## Architecture

The content path runs offline as CLI subcommands of one binary (`cmd/aicc-knowledge`). Each step hands the next one its work through PostgreSQL state and the `jobs` queue (`internal/jobs`, `FOR UPDATE SKIP LOCKED`, leases, one job per dedupe key).

1. **`scan`** (`internal/scan`, `internal/s3store`):
   - Polls ListObjectsV2. A changed object is downloaded, and its SHA-256 is its identity.
   - Inserts an immutable `file_versions` row, supersedes the old one, and marks the old version's candidates `STALE`.
   - A deleted object becomes `REMOVED`. Then it enqueues a PARSE job.
2. **`parse`** (`internal/parse` on top of the pure parsers `internal/docx` and `internal/xlsx`):
   - Writes `parsed_sections`. Their identity is `(file_version_id, ordinal)` plus `source_ref`, never the row id, because sections are rewritten.
   - Imports facts: `<name>.facts.yaml` next to `<name>.xlsx` maps sheets to typed `fact_rows` (`internal/facts`). A failed import makes the table `UNAVAILABLE`; stale or partial rows are never served.
   - Then it enqueues a GENERATE job.
3. **`generate`** (`internal/generate`, `internal/llm`, `internal/candidate`):
   - One LLM call per section, using JSON-schema output and a versioned prompt.
   - Deterministic post-validation (length, markdown, language, dedupe) and the `CONTAINS_FIGURES` flag.
   - Inserts candidates as `PENDING_REVIEW`.
   - `candidate.ContentHash` is the single hash used by generate, export and import.
4. **`export-review` / `import-review`** (`internal/review`): the Excel round trip. The import uses a savepoint per row and writes the `candidate_reviews` audit table.
5. **`publish` / `rollback`** (`internal/publish`, `internal/meili`, `internal/embed`):
   - **Publish:**
     - Snapshot the APPROVED candidates of current versions into `publication_items`.
     - Embed every phrasing with TEI and build a staging index.
     - Wait for every Meilisearch task, then swap with `faq_<lang>`, then commit `LIVE`.
   - **Swap behavior:** `/swap-indexes` exchanges contents, so `publications.content_uid` tracks where each publication's documents live.
   - **Rollback:** swaps back, or rebuilds from the snapshot when the index was pruned.

The read path is `serve` (`internal/httpapi` on the generated `internal/api`, plus `internal/search`):
- `POST /v1/search` embeds the query, runs a pure-vector Meilisearch search with a per-language `rankingScoreThreshold`, and reports per-stage latency. It never queries PostgreSQL, because the live uid only ever holds published content.
- `POST /v1/facts/{table}/lookup` is an exact-match lookup in PostgreSQL.
- A separate unauthenticated ops listener serves `/metrics`, `/healthz` and `/readyz`. Readiness probes TEI at `/info`, because TEI's `/health` runs an inference and queues behind load.

`eval` (`internal/eval`) runs the same search code in process and reports recall@3, NO_MATCH precision, latency p50/p90, and a `--sweep` over thresholds.

## Binding decisions (do not re-litigate)

- **Stack:** Go single binary; chi v5, pgx v5, sqlc, goose (migrations at startup), PostgreSQL 18, no pgvector.
- **Contract-first:** `docs/openapi.json` is the source of truth, then oapi-codegen; oasdiff runs in CI. Change the spec, run `make api-generate`, then implement `api.ServerInterface`. Never add a route the contract does not declare.
- **Naming** follows AICC's `docs/design/07-naming.md` (sibling repo, read only, never imported):
  - JSON lowerCamelCase; Go initialisms capitalized; DB snake_case.
  - Enums are SCREAMING_SNAKE and byte-identical everywhere. In Go: a named string type plus consts, no `iota`. In the DB: `varchar(N)` with a CHECK.
  - Errors return codes, never strings: `{"error":{"code","message","params"}}`, including router 404 and 405.
- **Configuration:** no multi-tenancy and no hardcoded endpoints. Config comes from `KB_*` env vars only (`internal/config`), and `.env.example` is the registry. Service URLs have no default in code.
- **S3:** aws-sdk-go-v2 with a configurable endpoint and path-style addressing. Change detection is by ListObjectsV2 polling only, with no event notifications.
- **Formats:**
  - `.docx` is parsed with the stdlib; headings come from the `styles.xml` `outlineLvl`, never from style names.
  - `.xlsx` is parsed with excelize.
  - `.doc` and `.xls` are `UNSUPPORTED_FORMAT`. No PDF, no OCR.
- **Embeddings:** TEI (CPU) serving bge-m3. Meilisearch `userProvided` vectors, one index per language (`faq_en`, `faq_zh`), and one vector per question phrasing.
- **Publishing:** nothing unreviewed is ever published. Publish builds a new index, then swaps it atomically; every publication is versioned.
- **Admin:** operations are CLI subcommands. The HTTP API serves only AICC's read paths and health.

## State machines (`internal/domain`, every edge tested)

- **File version:** `DISCOVERED → PARSED | PARSE_FAILED | UNSUPPORTED`, and any of them → `REMOVED` (terminal). `PARSE_FAILED → DISCOVERED` is the only retry edge, used by `parse --retry-failed`. A content change inserts a new version and never mutates the old one.
- **Candidate:** `PENDING_REVIEW → APPROVED | REJECTED`. Any state → `STALE` (terminal) when the source version is superseded or its section is withdrawn.
- **Publication:** `BUILDING → LIVE | FAILED`, `LIVE → SUPERSEDED`, and `SUPERSEDED → LIVE` for rollback. Rollback demotes the current LIVE row in the same transaction. At most one LIVE per language. Each language allows one publish or rollback at a time (advisory lock).
- **Job:** `QUEUED → RUNNING → SUCCEEDED | FAILED`, plus `RUNNING → QUEUED` for a retry or an expired lease.

## Conventions

- **Tests first**, against real PostgreSQL and real Meilisearch, never mocked. TEI should be real; a fake is allowed only in unit tests. LLM tests may use `internal/llm/llmtest`.
  - `internal/testdb.ScratchDSN` gives each test a throwaway database.
  - Assert cardinality next to equality.
  - Run with `-race`.
- **CI skips:** CI fails on any skip not listed in `.ci-allowed-skips.txt`. Never allowlist a test because a service is missing; add the service to `.github/workflows/ci.yml` instead.
- **Gate tests catch drift between sources of truth:**
  - Go enums equal the DB CHECK constraints.
  - The spec's `ErrorCode` equals the Go `Code*` consts.
  - Spec property names are lowerCamelCase, and spec enums are SCREAMING_SNAKE.
  - Every operation is routed and has bearer security.
  - `.env.example` equals the keys that config reads.
  - Every file has an SPDX header (`internal/repocheck`).
- **SPDX:** every Go, SQL, shell, YAML and Makefile file starts with `SPDX-License-Identifier: Apache-2.0`. Generated sqlc output is exempt.
- **Migrations:** `internal/store/migrations/NNNNN_snake_sentence.sql`, each with a prose header saying why, plus a real Down. Never edit a migration that has already been applied; add a new one. The store tests run up, down and up again.
- **Metrics:** names live in `internal/obs/metrics.go`. Do not state performance figures in docs or commits unless `eval` measured them.
- **TASKS.md is the plan:** the first unchecked item is the cursor. Check an item only after it is verified against live services.
- **No attribution:** do not add attribution lines to commits, PRs, issues or release notes.
